# Agent Notes

## Project Overview

This file is intended to live at the repository root.
Paths in this document are relative to the repository root.

`main-be` is a Python 3.13 FastAPI backend. The app entrypoint is
`src/main.py`, with feature modules under `src/`:

- `auth`: registration, authentication, users, avatars
- `app`: app metadata/services
- `calorie`: day, product, ingestion, and trend workflows
- `social`: teams/friendship workflows
- `notification`: verification code and email notification flows

The project uses SQLAlchemy async sessions, Alembic migrations, Pydantic v2,
Dependency Injector, Docker Compose, Ruff, and Pytest.

## Environment

- Python: `>=3.13`
- Package manager: `uv`
- Local configuration is read from `.env` using nested names with `__`, for
  example `DB__HOST`, `DB__USER`, `OPENAI__API_KEY`.
- Docker Compose services expect `.env` values for Postgres and application
  settings.
- Runtime imports rely on `PYTHONPATH=src` locally or `/app/src` in Docker.

Useful local setup:

```sh
uv sync --group dev
```

Useful Docker setup:

```sh
task d:build
task d:up
```

The API runs on `http://localhost:8000` when using the Compose `fastapi`
service. Mailpit is exposed on `http://localhost:8025`.

Do not create, modify, print, or commit real `.env` secrets.
Use `.env.example` or placeholder values when documenting configuration.

## Common Commands

Run formatting and lint fixes:

```sh
task format
```

Run tests:

```sh
task test
```

Run the default validation task:

```sh
task
```

Run migrations:

```sh
task m:upgrade
```

Create an autogenerated migration:

```sh
task m:new MSG="describe change"
```

Rollback one migration:

```sh
task m:downgrade
```

If `task` is unavailable, use the underlying commands:

```sh
ruff check . --fix
ruff format
pytest
docker compose -f deploy/compose.dev.yml run --rm develop alembic upgrade head
```

Prefer `task` commands when available because they match the project workflow.
Use the underlying commands only when Taskfile is unavailable.

## Architecture Conventions

- Routers live in each feature module as `router.py` and are included from
  `src/main.py`.
- Request and response schemas live in each feature module's `models.py`.
- SQLAlchemy ORM models live in each feature module's `orm.py`.
- Data access classes extend the shared repository style in
  `src/repository.py`.
- Business logic belongs in `services.py` or files under a feature module's
  `services/` package.
- Cross-feature service construction is centralized in
  `src/config/containers.py`.
- FastAPI dependencies are declared in `src/config/dependencies.py`.
- Database work should go through `UnitOfWork` from `src/unitofwork.py`.

When adding a new feature module, wire its router in `src/main.py`, import its
ORM models in `migrations/env.py` for Alembic autogeneration, and add required
providers to `Container`.

## Database and Transactions

- The app uses async SQLAlchemy sessions.
- Repositories should not create sessions directly; use the injected
  `UnitOfWork`.
- Service methods that mutate state should explicitly call `await uow.commit()`
  after successful writes.
- `UnitOfWork.__aexit__` rolls back and closes the session, so uncommitted work
  is discarded.
- Alembic uses settings from `.env` through `src/config/settings.py`.

## API Response Shape

Routers generally return `ResponseDTO[...]` from `src/models.py`. Error
responses are normalized in `src/main.py`:

- FastAPI validation errors return `{"error": {"errors": ...}}`
- `HTTPException` returns `{"error": {"message": ...}}`

Preserve this shape when adding endpoints.

## Code Style

- Ruff is configured in `pyproject.toml` with line length `88`.
- Imports are sorted by Ruff's `I` rules.
- Use double quotes for formatted code.
- Keep code typed where practical; existing code uses modern Python union
  syntax such as `str | None`.
- Prefer small service methods and feature-local DTOs over adding shared
  abstractions too early.

## Testing Notes

- Tests are run with `pytest`.
- Add focused tests for service logic when changing calculations, validation,
  authorization, or repository behavior.
- For database-backed changes, prefer tests that exercise the service boundary
  unless the repository query itself is the behavior under test.

## External Services

- OpenAI access is wrapped by `src/calorie/openai_client/`.
- S3 access is wrapped by `src/clients/s3.py`.
- Email delivery uses FastAPI-Mail and defaults to Mailpit-compatible local
  settings.
- Sentry only initializes when `PRODUCTION=true`.

Avoid calling external services directly from routers. Keep integrations behind
client or service classes so they can be replaced in tests.

## Git Hygiene

- Do not commit generated caches such as `__pycache__`, `.pytest_cache`, or
  `.ruff_cache`.
- Treat untracked or modified files as user work unless explicitly told
  otherwise.
- Keep migrations and model changes in sync: ORM changes that affect schema
  should include an Alembic migration.

## Before Finishing

- Run `task format` after code changes.
- Run `task test` for behavioral changes.
- Run `task` for the full validation pass when practical.
- Mention any tests or checks that could not be run.
- Mention any required migration, environment variable, or deployment change.
